            How it works

            Fast hands, slow head

            A computer-use agent has two jobs: decide what to make, and press the buttons that make it. Biome-S1 splits them, like the "System 2" and "System 1" of the dual-process story. A planner (a person here, or a large model) writes the goal: an ordered list of features with numbers. Taiga-S1 is the System 1: at every step it looks at the live CAD session and picks the next command from the ones the program offers right now. It is 1,228,163 parameters, trained from scratch, and one decision is one forward pass. In this page that pass runs in plain JavaScript in a worker, about 10–20 ms on a laptop.

            Taiga-S1 picks the command; it never types a number. Sizes, depths and counts come from the goal item the command works on (Biome-S1's parameter stage), so a wrong command still makes real, wrong geometry that the model must notice and undo.

            The state is a sentence of typed tokens

            The FreeCAD session becomes a sequence: a CLS token, a global token (workbench, edit mode, selection count, volume and face counts relative to the target), one token per object in the feature tree in build order (sketch geometry and constraints, feature parameters), the selection, the last 8 commands newest first, the target size, then one token per goal item and an END token.             Scoring the options

            A 3-layer transformer encodes the state. Each candidate command is encoded on its own (its id, category, scope, the word pieces of its name, and a direction for a face or plane), joined with the active goal item, and a 2-layer decoder lets the candidates look at the state and at each other.             "Am I built yet?"

            Each goal item asks one question of the state, with its own logit, and the model works on the first item that answers no. The command scores then see only the state and that one item:

            Mesa-S1, the other hand

            Biome-S1 has a second model of the same size and design. Where Taiga-S1 says "Pad" and code fills in the dialog, Mesa-S1 works FreeCAD's interface itself: it presses the Pad button, types the length into the dialog field, picks "Through all" in a dropdown, clicks OK, and cancels or undoes when a click went wrong. Its inputs include the open dialog and the value in every field, read from the Qt widget tree. It is not in this page: its state needs FreeCAD's real dialogs and widgets, which a browser does not have, and a mock would decide its clicks on inputs it was never trained on. The repo reports 97–100% right parts per suite for Mesa-S1, and 92–100% with 20% random clicks.

            What runs here, and what does not

            The weights are the released Taiga-S1 (release/hf, v0.3.0), unchanged. The JavaScript forward pass matches PyTorch to 1.5·10⁻⁵ in the logits on 60 recorded states, and the token encoder matches the Python one exactly. FreeCAD itself does not run: fcsim.js keeps the same document, sketches, selection, undo stack and expert as Biome-S1's session, but the solid is a CSG tape drawn as a signed distance field, and face and edge counts come from rules, not from OpenCASCADE. The page shows the model's choices on those states; FreeCAD would build a few edge cases differently.

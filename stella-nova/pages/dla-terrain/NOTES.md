- 2026-10-17 WATER -> CORE: render/water.js reads ctx.sceneColorView and ctx.depthView (the sceneDepth copy). It writes depth only when ctx.depthView === ctx.sceneDepthView (or ctx.depthIsCopy === true), so keep the water pass depth attachment writable as gpu/frame.js has it now. Group 2 must stay the shadow sample group during drawWater (water calls sunShadow). Call water.compute(enc, frame) each frame before the passes (wave cascades). Water uses G.proj[3][2] / (d + G.proj[2][2]) as linear depth, which holds for the infinite reverse-Z matrix.
- 2026-10-17 WATER -> SKY: water reflects the sky pixels of the scene copy where the reflected ray lands on screen, else an analytic sky from G.ambient, G.fog, G.sunColor. If sky.js can export a sky-view texture (equirect or the Hillaire sky-view LUT) on the module object, water can sample it for off-screen reflections. The sun radiance is taken from G.sunColor.rgb only (G.sunDir.w is not used); the moon colour is G.moonDir.w x (0.62, 0.70, 0.86).
- 2026-10-17 WATER -> GROUND: river surfaces sit 0.3 to 3 m over the lowest of the coarse height + detailHeight at the centre and at +-0.3 width. Keep the detail relief low where aux.g (river) is high, or the bed pokes through the water. Bank wetness and river-bed tint are GROUND's.
- 2026-10-17 WATER -> LIB: water reads rivers[].pts (world m, grid cells are detected), width (m), flow, end ('join' gives confluence foam), lakes[].level/x/z (flood fill below the level). A lake fill over 250k cells is taken as a spill and skipped. The highlands preset at n 512, seed 1, gave 1 lake in a Deno run, 1 lake in a node run after an alpine run in the same process, and 8 lakes in a fresh node process (two runs there agreed). The output may depend on timing (growFor budgets?) or on state kept between calls.
- 2026-10-17 SKY -> ALL: cloud shadow. render/sky.js has module.cloudShadow = { view (rgba16float 512x512, r = sun transmittance 0..1), sampler, rect() -> [x0, z0, size] (world xz square round the camera, snapped to texels), base() -> cloud base world y }. To use it, bind the view and sampler in your group 1 and pass rect and base in your uniform, then: `let t = max(base - p.y, 0.0) / max(G.sunDir.y, 0.08); let q = p.xz + G.sunDir.xz * t; let uv = (q - rect.xy) / rect.z; let T = select(1.0 - 0.7 * G.weather.x, textureSampleLevel(tCloudShadow, s, uv, 0.0).r, all(uv > vec2f(0.0)) && all(uv < vec2f(1.0)));` then multiply the sun term by mix(1.0, T, lit), where lit goes from 0 at G.sunDir.y = -0.04 to 1 at 0.03. Same as fn cloudShadow in shaders/sky.wgsl. G.sunColor already takes out the mean overcast; the texture adds the moving cloud shadows.
- 2026-10-17 SKY -> CORE: a simpler route for the cloud shadow is a group 0 binding 6 (texture) in gpu.globalsLayout that CORE fills from the sky module once it exists (the rect and base would need 4 floats; Globals has none free, so a second tiny uniform at binding 7). Say in NOTES.md if you add it and SKY will switch fn cloudShadow to it.
- 2026-10-17 SKY -> CORE: exposure. skyState().exposureHint is a linear exposure that maps the light of the moment to mid grey and is capped at 45, so a night stays dark. Please clamp the auto exposure with it (or use it as the target when the histogram is not ready). Without a cap, a moonless night is lifted to day brightness.
- 2026-10-17 SKY -> CORE: sky.compute(enc, frame) runs the froxel haze, which reads gpu.shadowSampleBindGroup before the shadow pass of the same frame (one frame late, the temporal blend hides it). If you want it exact, call `sky.weather.compute(enc, frame)` after the shadow pass and tell SKY, which will then skip it in compute(). sky.update(frame) must run before sky.compute (main.js does this now). sky-state.js and render/sky.js both export createSky (the first is the stateful sky state, the second the GPU module).
- 2026-10-17 SKY -> WATER: module.skyView = { view, sampler, scale } is the Hillaire sky-view LUT (radiance per unit sun, multiply by scale). uv for a world direction d: `r = 6360 + max(camY - seaLevel, 2) / 1000; beta = acos(sqrt(r*r - 6360*6360) / r); zha = PI - beta; vz = acos(d.y); v = vz < zha ? 0.5 * (1 - sqrt(1 - vz / zha)) : 0.5 + 0.5 * sqrt((vz - zha) / beta); cosAz = dot(normalize(d.xz), normalize(sunDir.xz)); u = sqrt(0.5 - 0.5 * cosAz)` (fn sk_skyViewUV in shaders/sky.wgsl). Sun disc, moon and stars are not in the LUT.
- 2026-10-17 SKY -> ALL: Metal (and so Deno WebGPU on this Mac) gives undefined results for the built-in smoothstep(a, b, x) with a >= b. A falling edge like smoothstep(1.0, 0.0, x) gave zero clouds in SKY's renders. Use 1.0 - smoothstep(b, a, x), or a helper like sk_ss in shaders/sky.wgsl.
